Bu dosya, Yaverim projesini Cursor + Claude ile tek parça ve düzenli şekilde build etmek için hazırlanmış ana referans dosyasıdır.

Bu dosya:
- marka kimliğini

- veri modelini

## 2. Ürün Tanımı

Yaverim bir “AI tool listesi” değildir.

Yaverim:
- kullanıcıyı anlar
- iş modelini ve hedefini çözer
- bağlama uygun çözüm alanlarını çıkarır
- doğru AI araçlarını önerir
- ücretsiz ve ücretli seçenekleri dengeler
- premium katmanda uygulanabilir plan üretir

## 17. Claude / Cursor İçin Master Build Prompt

Aşağıdaki prompt, Claude 4.5 Sonnet / Cursor içinde ana build prompt olarak kullanılacaktır.

```md
You are building a production-minded V1 web product called **Yaverim**.

## Product identity
- Brand name: Yaverim
- Domain: Yaverim.io
- Primary language: Turkish
- Slogan: "Yaverim sana yarayanı bulur."
- Hero heading: "İhtiyacına en uygun yapay zekâ araçlarını bul."

## Product definition
Yaverim is a Turkish recommendation engine that helps individuals, freelancers, founders, small businesses, and SMEs discover the AI tools, solution areas, and action plans that fit their actual goals, constraints, and workflows.

This is NOT a generic AI tools directory.
This product must:
- understand user context
- classify user type, business model, goals, team structure, and budget
- recommend only context-relevant solution areas
- show a strong free summary result
- upsell a premium detailed plan
- support affiliate / partner monetization without corrupting editorial trust

## Design direction
- Light-first
- Clean, modern, editorial, calm
- No fake luxury
- No neon-heavy SaaS clichés
- No cluttered dashboards
- Background should subtly communicate a living AI ecosystem
- Hero can include slow-moving AI ecosystem cards/logos as atmospheric background, not as distracting carousel

## Home page sections
1. Hero
2. Mini onboarding entry
3. How it works
4. Example result experience
5. Top 10 area
6. Premium value area
7. Trust principles
8. SEO discovery blocks
9. Footer

## Analyze / onboarding flow
Build a short, controlled, chat-like onboarding with these inputs:
1. Who are you?
2. What do you do?
3. What do you want to improve most?
4. How do you work?
5. What is your budget approach?
6. Optional free-text details

Keep it fast, simple, and non-overwhelming.

## Results page structure
1. Short diagnosis
2. Decision summary
3. Why these suggestions
4. Solution areas
5. Mini recommendation cards
6. Premium preview
7. Unlock CTA
8. Extra exploration

### Decision summary must include:
- Best fit
- Free alternative
- Stronger alternative

## Premium logic
Premium is NOT just “more tools”.
Premium sells an actionable plan.

Premium page must include:
- top summary
- priority map
- dynamic 3–5 stage plan
- first stage open by default
- other stages collapsible
- stage-specific tool blocks
- effect summary
- “what is expected from you” section
- PDF included

Each premium stage must include:
- purpose
- why this stage comes now
- recommended tools
- implementation steps
- warnings / pitfalls
- exit criteria before next stage

## Monetization logic
- Free summary first
- Do NOT ask for money before value is shown
- Premium unlock happens after summary
- PDF is included once premium is unlocked
- Support both one-time unlock and subscription
- Subscription adds saved plans, history, favorites, re-analysis, advanced comparison, scenario creation

## Top 10 logic
Public ranking should always use Top 10 format.
Build reusable rectangular cards for ranking items.
Each card should include:
- rank number
- logo
- tool name
- strongest use case
- 2–3 strong signals
- actions like inspect / compare

Important:
Any tool shown in Top 10 must also exist in the core recommendation universe.

## Recommendation engine logic
Implement product logic conceptually around:
1. Rule-based filtering
2. Score-based ranking
3. LLM explanation layer

Score axes:
- fit to need
- ease of use
- price / value
- productivity impact
- growth impact
- optional integration fit

Do not rely on pure LLM reasoning for the entire decision stack.
The system should be explainable and structured.

## Trust rules
- Sponsored visibility must be explicitly labeled
- affiliate relationship must not affect core scoring
- non-monetized but correct tools can still be recommended
- no fake certainty
- no exaggerated guaranteed ROI language

## Tech stack
Use:
- Next.js App Router
- TypeScript
- Tailwind CSS
- Prisma
- PostgreSQL
- Vercel-oriented architecture

## Performance
The site must feel fast and stable.
- optimize first-load experience
- keep heavy content progressively disclosed
- avoid bloated dashboards
- use clean loading states
- design for smooth user experience on desktop and mobile

## Deliverables
Generate the V1 project structure, key pages, reusable components, and code architecture in a clean, scalable way.
Favor maintainability, clarity, and future team collaboration.
Do not build a throwaway MVP.
Build a clean V1 foundation that can scale.
```
